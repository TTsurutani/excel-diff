# サブキーによるフォールバック照合をキーJOINモードに追加する

キーJOINモードで主キーによる対応付けが確定しなかった行（空欄キー／重複キーの残り／有効な一意キーだが相手側に存在しない行）を「未マッチプール」とし、主キー照合の直後に、任意のサブキー列によるもう一段の照合ステージを挿入する。サブキーは未マッチプール同士（旧・新とも主キーで解決できなかった行）だけを対象にし、サブキー値が旧・新それぞれちょうど1件のときのみ確定マッチとする。1件でも0件・2件以上といった曖昧な一致は行わず、安全側（未マッチのまま次段へ）に倒す。

サブキーで救済できなかった行は、元の由来によって行き先を分ける。空欄キー／重複キー由来の行は、従来通り既存のLCS（順序ベース類似度）フォールバックへ渡す。有効な一意キーを持つが相手側に存在しなかった行は、そのままDELETE/INSERTとして確定する（LCSは経由しない）。後者にLCSを経由させないのは、`sub_key_cols`未設定時の既存挙動に一切影響を与えないため、かつサブキーは主キーに対する1段階のみのフォールバックとする方針（後述）を保つためである。

サブキーで対応付いたペアに限り、旧・新の主キー列の値そのものが食い違っている（定義上）ため、その主キー列も通常の差分比較対象列として扱う。主キー一致で対応付いたペアはこれまで通り対象外のまま。HTML出力ではこの主キー列のセルに専用の背景色（`#e8dcff`）を付けて区別するが、行番号セルの着色（EQUAL/DELETE/INSERT/MODIFYの4分類）は変更しない — 行番号は「行ステータス」だけを表す単一の意味に保ち、「どう対応付いたか」はセル単位の色で表現する。

サブキーの一致判定自体は主キーと仕様を揃える：マッチャー（mapping/equivalence）は使わず正規化済みの生値の厳密一致のみ、`--include-cols`によるフィルタとは独立、実行全体で1つのグローバル設定（シート単位の個別指定はスコープ外）。主キー列とサブキー列の重複指定、および`sub_key_cols`が指定されているのに`diff_mode`がkeyでない／`key_cols`が空、という設定は起動時エラーとする。CLIとGUI（シート比較・ファイル比較・フォルダ比較の3タブ、プロファイル保存含む）の両方に実装し、機能差を作らない。

## Considered Options

- 曖昧一致を順序や優先順位で機械的に1件選んで確定させる案 → 却下。再現性が低く、誤結合のリスクが安全側フォールバックより大きい。
- 未マッチプール全体（空欄/重複キー由来＋有効キーだが相手不在の行）を一律で既存LCSフォールバックに合流させる案 → 却下。`sub_key_cols`未設定時の既存挙動（有効キーだが相手不在の行は無条件でDELETE/INSERT）に影響を与えてしまうため、由来ごとに行き先を分ける方式を採用した。
- サブキー救済されたことを行番号セルの色でも示す案 → 却下。行番号は行ステータスのみを表す単一責務のチャネルとして維持し、対応付け方式の情報はセル単位の色に一本化する。

## Consequences

主キー列が`--include-cols`で差分表示から除外されている場合、サブキー救済ペアであっても専用色は表示されない（既存の除外列の挙動がそのまま適用されるだけで、特別な救済表示は用意しない）。
